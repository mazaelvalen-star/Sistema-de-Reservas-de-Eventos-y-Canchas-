# Proyecto Final

## Sistema de Eventos de un Complejo

## Descripción del proyecto

## 📌 Descripción del Proyecto

El presente proyecto propone el desarrollo de un **Sistema de Eventos para un Complejo**, diseñado con el objetivo de facilitar la organización, administración y control de los diferentes eventos que se realizan dentro de sus instalaciones.

El sistema permitirá centralizar en un único lugar toda la información relacionada con los eventos y sus reservas, evitando depender de anotaciones manuales, mensajes o registros separados que pueden generar confusiones, pérdida de información o superposición de fechas y horarios.

Dentro del complejo se podrán administrar diferentes espacios destinados a la realización de eventos, como **salones, quinchos, cantina y otros sectores disponibles**. Cada espacio contará con información propia que permitirá identificarlo y conocer su disponibilidad.

A través del sistema será posible **registrar los datos de los clientes**, seleccionar el espacio solicitado, establecer la fecha y el horario del evento y registrar la correspondiente reserva. Toda esta información quedará almacenada para poder ser consultada posteriormente.

El sistema también contará con un **calendario de disponibilidad**, que permitirá visualizar de manera sencilla qué fechas y horarios se encuentran libres y cuáles ya poseen eventos programados. De esta manera, antes de registrar una nueva reserva se podrá verificar la disponibilidad del espacio y evitar superposiciones.

Además de registrar nuevas reservas, se podrán **consultar, modificar y cancelar reservas existentes**, permitiendo mantener actualizada la planificación de los eventos ante posibles cambios solicitados por los clientes.

Como característica adicional, cuando un espacio o una fecha solicitada no se encuentre disponible, el sistema podrá mostrar **otras alternativas disponibles**, facilitando la búsqueda de una opción adecuada sin necesidad de revisar manualmente cada espacio o fecha.

La información principal del sistema será almacenada en una **base de datos**, permitiendo mantener relacionados los clientes, los espacios y las reservas realizadas. Esto permitirá contar con información organizada y disponible para su consulta cuando sea necesario.

El desarrollo estará orientado a obtener un sistema **simple, organizado e intuitivo**, priorizando las funciones necesarias para la correcta gestión de los eventos y dejando abierta la posibilidad de incorporar nuevas funcionalidades en futuras versiones.

## 💡 Justificación del Proyecto

La organización de eventos dentro de un complejo requiere llevar un control preciso de los espacios disponibles, las fechas, los horarios, los datos de los clientes y las reservas realizadas. Cuando esta información se administra de manera manual, mediante anotaciones, agendas, planillas separadas o conversaciones por mensajería, pueden surgir dificultades para mantener los datos organizados y actualizados.

Uno de los principales problemas que pueden presentarse es la **superposición de reservas**, es decir, registrar dos eventos para un mismo espacio en una fecha y horario coincidentes. También pueden producirse errores al consultar la disponibilidad, pérdida de información de los clientes, dificultades para localizar una reserva determinada o demoras al momento de ofrecer otras opciones cuando el espacio solicitado ya se encuentra ocupado.

A partir de esta problemática surge la necesidad de desarrollar un **Sistema de Eventos para un Complejo**, que permita centralizar la información y facilitar la gestión de los eventos desde una única herramienta.

La implementación del sistema permitirá disponer de un registro organizado de los **clientes, espacios, fechas, horarios y reservas**, haciendo posible consultar rápidamente la información necesaria para gestionar cada evento.

La incorporación de un calendario de disponibilidad contribuirá a mejorar la planificación, ya que permitirá identificar de forma clara los espacios que se encuentran libres u ocupados antes de registrar una nueva reserva. Esto ayudará a reducir errores y evitar conflictos relacionados con la asignación de fechas y horarios.

Además, ante la falta de disponibilidad de un espacio o fecha determinada, el sistema podrá facilitar la búsqueda de **alternativas disponibles**, permitiendo consultar otras opciones sin tener que revisar manualmente todos los registros existentes.

Otro aspecto importante es la posibilidad de **modificar o cancelar reservas**, manteniendo actualizada la información cuando se produzcan cambios en la planificación de un evento.

La utilización de una base de datos permitirá conservar la información de forma estructurada y relacionar correctamente cada reserva con el cliente y el espacio correspondiente, facilitando posteriormente su consulta y administración.

Por estas razones, el desarrollo del proyecto busca proporcionar una solución tecnológica que permita **optimizar la organización de los eventos, reducir errores administrativos, agilizar la consulta de información y mejorar el control de los espacios disponibles dentro del complejo**.

Asimismo, el proyecto permitirá aplicar de manera práctica los conocimientos adquiridos durante la carrera, integrando conceptos relacionados con análisis y diseño de sistemas, bases de datos, programación, desarrollo de interfaces y gestión de proyectos.

## Alcance y limitaciones
## 📍 Alcance del Proyecto

El proyecto abarcará el desarrollo de un **Sistema de Eventos para un Complejo**, orientado a centralizar y organizar la información necesaria para la gestión de los espacios y las reservas de eventos.

El sistema permitirá administrar el proceso de una reserva desde el registro inicial del cliente hasta la confirmación, modificación o cancelación del evento, manteniendo toda la información relacionada almacenada de manera organizada.

Dentro del alcance del proyecto se incluirán las siguientes funcionalidades:

- **Gestión de clientes:** permitirá registrar, consultar, modificar y eliminar los datos de los clientes asociados a las reservas.

- **Gestión de espacios:** permitirá registrar y administrar los diferentes espacios disponibles dentro del complejo, como salones, quinchos, cantina u otros sectores destinados a la realización de eventos.

- **Gestión de reservas:** permitirá crear nuevas reservas relacionando un cliente con un espacio, una fecha y un horario determinado.

- **Consulta de disponibilidad:** permitirá verificar si un espacio se encuentra disponible antes de registrar una nueva reserva.

- **Calendario de eventos:** permitirá visualizar de manera organizada las fechas y horarios que se encuentran disponibles u ocupados.

- **Control de superposiciones:** el sistema verificará que no exista otra reserva para el mismo espacio en una fecha y horario coincidentes.

- **Modificación de reservas:** permitirá actualizar la información de una reserva cuando se produzcan cambios en la fecha, horario, espacio o datos correspondientes.

- **Cancelación de reservas:** permitirá cancelar una reserva y liberar nuevamente el espacio y horario correspondiente.

- **Búsqueda y consulta:** permitirá localizar reservas y acceder a su información de manera rápida y organizada.

- **Alternativas de disponibilidad:** cuando un espacio, fecha u horario solicitado no se encuentre disponible, el sistema podrá mostrar otras opciones disponibles.

- **Almacenamiento de información:** los datos correspondientes a clientes, espacios y reservas serán almacenados en una base de datos para permitir su posterior consulta y actualización.

El sistema será desarrollado de manera modular, permitiendo que sus diferentes funciones se encuentren organizadas y que puedan incorporarse nuevas características en futuras versiones sin modificar completamente la estructura existente.

El alcance de esta primera versión estará enfocado principalmente en lograr una correcta **gestión, organización y control de los eventos y reservas del complejo**.


## ⚠️ Limitaciones del Proyecto

El desarrollo del **Sistema de Eventos de un Complejo** estará enfocado en las funciones principales necesarias para la organización y gestión de espacios, clientes y reservas. Por tratarse de una primera versión del sistema, se establecerán ciertas limitaciones con el objetivo de mantener un alcance adecuado y posible de desarrollar.

## ⚠️ Limitaciones del Proyecto

El desarrollo del **Sistema de Eventos de un Complejo** estará centrado principalmente en la organización de clientes, espacios, tarifas y reservas de eventos. Para mantener un alcance posible de desarrollar, la primera versión del sistema contará con determinadas limitaciones.

Las principales limitaciones serán:

- **Sin pagos en línea:** el sistema podrá informar y registrar el valor correspondiente a una reserva, pero no permitirá realizar el pago directamente mediante Mercado Pago, tarjetas, transferencias u otras plataformas.

- **Sin facturación electrónica:** el sistema no estará conectado con servicios externos de facturación y no generará comprobantes fiscales electrónicos.

- **Tarifas definidas por el complejo:** el valor de cada reserva dependerá de las tarifas previamente registradas para clientes afiliados y no afiliados. El sistema no calculará promociones o descuentos externos que no hayan sido definidos previamente.

- **Disponibilidad limitada a los espacios registrados:** solamente podrán consultarse y reservarse los espacios para eventos que hayan sido cargados previamente en el sistema.

- **Dependencia de la información registrada:** para mostrar correctamente la disponibilidad, las nuevas reservas, modificaciones y cancelaciones deberán mantenerse actualizadas en el sistema.

- **Sin aplicación móvil propia:** en esta primera versión no se desarrollará una aplicación específica para Android o iOS.

- **Gestión limitada de servicios adicionales:** el sistema estará orientado principalmente a la reserva de espacios. Servicios complementarios como catering, decoración, sonido, iluminación o contratación de personal no serán gestionados de forma completa en esta primera versión.

- **WhatsApp como canal complementario:** la comunicación mediante WhatsApp estará destinada principalmente a responder consultas frecuentes y permitir que el cliente solicite atención de una persona encargada. No reemplazará las funciones administrativas principales del sistema.

Estas limitaciones permiten establecer un alcance realista para la primera versión del proyecto, priorizando el correcto funcionamiento de la gestión de **clientes, afiliaciones, tarifas, espacios y reservas de eventos**.

Las funcionalidades adicionales podrán ser consideradas como futuras mejoras del sistema.

 ## Estructura del programa

El sistema estará organizado en diferentes partes, donde cada una tendrá una función específica dentro del programa.

### 1. Inicio
Será la pantalla principal del sistema.

Permitirá:
- Acceder al sistema.
- Visualizar las opciones principales.
- Ingresar a los diferentes módulos.

### 2. Gestión de clientes
Se encargará de almacenar y administrar la información de las personas que realizan una reserva.

Permitirá:
- Registrar clientes.
- Consultar clientes.
- Modificar sus datos.
- Eliminar clientes.

Datos principales:
- Nombre y apellido.
- DNI.
- Teléfono.
- Correo electrónico.

### 3. Gestión de espacios
Administrará los lugares disponibles para realizar reservas.

Los espacios podrán ser:
- Canchas de fútbol.
- Canchas de básquet.
- Canchas de pádel.
- Salón.
- Quinchos.
- Otros espacios para eventos.

Permitirá conocer qué espacios están disponibles y cuáles están ocupados.

### 4. Gestión de reservas
Será la parte principal del sistema.

Permitirá:
- Crear una reserva.
- Consultar reservas.
- Modificar una reserva.
- Cancelar una reserva.
- Seleccionar fecha y horario.
- Seleccionar el espacio que desea reservar.
- Asociar la reserva con un cliente.

Antes de registrar una reserva, el sistema verificará que el espacio no esté ocupado en esa fecha y horario.

### 5. Calendario de disponibilidad
Mostrará las fechas y horarios disponibles.

Permitirá:
- Visualizar días disponibles.
- Visualizar días ocupados.
- Consultar la disponibilidad de cada espacio.
- Evitar reservas duplicadas.

### 6. Alternativas de reserva
Si el espacio o el horario seleccionado está ocupado, el sistema podrá mostrar otras opciones disponibles.

Por ejemplo:
- Otro horario disponible.
- Otra cancha disponible.
- Otro espacio para eventos.

### 7. Administración
Permitirá gestionar la información general del sistema.

Desde esta sección se podrán administrar:
- Clientes.
- Espacios.
- Reservas.
- Fechas y horarios.

### 8. Base de datos
La base de datos almacenará permanentemente la información utilizada por el sistema.

Contendrá principalmente:
- Clientes.
- Espacios.
- Reservas.
- Horarios.

Las tablas estarán relacionadas para poder identificar qué cliente realizó una reserva, qué espacio reservó y en qué fecha y horario.

### 9. API / Backend
Será la parte encargada de comunicar el programa con la base de datos.

Se utilizarán operaciones como:

- GET: consultar información.
- POST: registrar nueva información.
- PUT: modificar información existente.
- DELETE: eliminar o cancelar información.

Por ejemplo:

GET /reservas → consultar reservas.

POST /reservas → crear una reserva.

PUT /reservas/{id} → modificar una reserva.

DELETE /reservas/{id} → cancelar una reserva.

## 🧩 Módulos del Sistema

El **Sistema de Eventos de un Complejo** estará dividido en diferentes módulos, cada uno encargado de realizar funciones específicas. Esta organización permitirá mantener el sistema ordenado y facilitar su desarrollo, mantenimiento y futuras ampliaciones.

Los módulos principales serán los siguientes:

### 👤 1. Módulo de Clientes

Este módulo estará destinado a la gestión de las personas que soliciten la reserva de un espacio para realizar un evento.

Permitirá:

- Registrar nuevos clientes.
- Consultar los clientes existentes.
- Modificar sus datos personales.
- Eliminar registros cuando corresponda.
- Registrar información como nombre, apellido, DNI, teléfono y correo electrónico.
- Identificar si el cliente es **afiliado o no afiliado al complejo**.
- Consultar las reservas asociadas a un determinado cliente.

La condición de afiliación será importante para determinar posteriormente la tarifa correspondiente a la reserva.

---

### 🏢 2. Módulo de Espacios

Este módulo permitirá administrar los diferentes espacios que el complejo ofrece para la realización de eventos, como salones, quinchos, cantina u otros sectores habilitados.

Permitirá:

- Registrar nuevos espacios.
- Consultar los espacios disponibles.
- Modificar la información de un espacio.
- Registrar su capacidad.
- Indicar si el espacio se encuentra habilitado para recibir reservas.
- Consultar su disponibilidad.
- Asociar las tarifas correspondientes.

De esta manera, el sistema mantendrá organizada toda la información relacionada con los lugares disponibles para eventos.

---

### 💳 3. Módulo de Tarifas y Afiliaciones

Este módulo permitirá administrar los diferentes valores establecidos por el complejo para la reserva de sus espacios.

El sistema diferenciará principalmente entre:

- **Clientes afiliados:** tendrán la tarifa establecida para afiliados.
- **Clientes no afiliados:** tendrán la tarifa general establecida para personas que no poseen afiliación.

Al momento de realizar una reserva, el sistema identificará la condición del cliente y mostrará el precio correspondiente al espacio seleccionado.

También permitirá actualizar las tarifas cuando el complejo realice modificaciones en sus valores.

---

### 📅 4. Módulo de Reservas

Será uno de los módulos principales del sistema y permitirá administrar las reservas correspondientes a los diferentes eventos.

Permitirá:

- Registrar una nueva reserva.
- Seleccionar el cliente que realiza la reserva.
- Seleccionar el espacio solicitado.
- Registrar la fecha del evento.
- Registrar el horario correspondiente.
- Determinar la tarifa según la condición del cliente.
- Consultar reservas existentes.
- Modificar una reserva.
- Cancelar una reserva.
- Consultar el estado de una reserva.

Cada reserva quedará relacionada con el cliente y el espacio correspondiente.

---

### 🗓️ 5. Módulo de Calendario y Disponibilidad

Este módulo permitirá visualizar de manera organizada la ocupación de los espacios del complejo.

Permitirá:

- Consultar las reservas según su fecha.
- Visualizar fechas y horarios disponibles.
- Identificar fechas y horarios ocupados.
- Comprobar la disponibilidad antes de confirmar una reserva.
- Evitar la superposición de dos eventos para un mismo espacio.
- Buscar otras opciones cuando la fecha, horario o espacio solicitado no se encuentre disponible.

Por ejemplo, si un cliente solicita un salón que ya está reservado para determinada fecha y horario, el sistema podrá informar que no se encuentra disponible y permitir consultar otras alternativas.

---

### 💬 6. Módulo de Comunicación y Atención

Este módulo estará destinado a facilitar la comunicación entre los clientes y el complejo mediante **WhatsApp**.

Permitirá brindar respuestas automáticas para determinadas consultas frecuentes, como:

- Información sobre los espacios.
- Tarifas para afiliados y no afiliados.
- Requisitos generales para realizar una reserva.
- Información relacionada con la disponibilidad.
- Orientación sobre el proceso de reserva.

Además, durante la comunicación se podrá ofrecer al cliente la posibilidad de solicitar atención personalizada mediante una opción como:

**¿Desea comunicarse con una persona encargada del complejo?**

- **Sí:** se solicitará la intervención de una persona encargada para continuar la atención.
- **No:** el cliente podrá continuar utilizando las opciones de atención automática.

De esta manera, se busca automatizar las consultas más sencillas sin eliminar la posibilidad de recibir atención por parte del personal del complejo.

---

### 🗄️ 7. Módulo de Base de Datos

Este módulo será responsable de almacenar y mantener organizada toda la información utilizada por el sistema.

La base de datos almacenará principalmente información relacionada con:

- Clientes.
- Afiliaciones.
- Espacios.
- Tarifas.
- Reservas.
- Fechas y horarios.
- Estados de las reservas.

Las diferentes tablas estarán relacionadas entre sí para garantizar que cada reserva pueda asociarse correctamente con su cliente, espacio y tarifa correspondiente.

---

### 🔗 8. Módulo de API y Backend

Este módulo será responsable de procesar las operaciones realizadas desde el sistema y establecer la comunicación con la base de datos.

Permitirá realizar las operaciones necesarias para:

- Registrar información.
- Consultar información.
- Actualizar registros existentes.
- Eliminar o cancelar registros.
- Verificar disponibilidad.
- Aplicar las reglas necesarias para evitar reservas superpuestas.
- Obtener la tarifa correspondiente según el tipo de cliente.

La API permitirá organizar la lógica del sistema y facilitar la comunicación entre la interfaz utilizada por el usuario y la base de datos.

### ⏱️ Consideraciones del Cronograma

El cronograma presentado representa una planificación inicial del proyecto. Algunas actividades podrán desarrollarse de manera simultánea o requerir más tiempo dependiendo de su complejidad.

Durante todo el proceso se mantendrá actualizado el repositorio de **GitHub**, registrando los avances realizados por los integrantes del equipo.

En caso de ser necesario, las etapas podrán reorganizarse sin modificar los objetivos principales del proyecto, priorizando el correcto funcionamiento de las funcionalidades esenciales antes de incorporar características complementarias.
